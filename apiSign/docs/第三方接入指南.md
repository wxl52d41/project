# 第三方接入文档

---

## 一、接入准备

| 项目 | 说明 |
|------|------|
| 服务地址 | 接口根地址 |
| appId | 你方唯一标识 |
| secretKey | 密钥，线下安全渠道传递 |
| digestAlgo | 摘要算法，如 `hmac-sha256`、`md5` |
| timestampDisparity | timestamp 与服务端时间差上限，单位毫秒 |

Java 项目依赖 `api-sign-core`：

```xml
<dependency>
    <groupId>com.wxl52d41</groupId>
    <artifactId>api-sign-core</artifactId>
    <version>1.0.0-SNAPSHOT</version>
</dependency>
```

非 Java 项目按第二章自行实现加签。

## 二、加签流程

### 2.1 四步

**第 1 步：收集参与签名的参数**

| 调用形态 | 参与签名的参数 |
|----------|--------------|
| query / form 参数模式 | 全部业务参数 |
| JSON body 模式 | body 展平后的全部字段 |
| 路径参数 | 路径变量也作为普通参数参与 |

**第 2 步：补齐 timestamp 和 nonce**

| 参数 | 要求 |
|------|------|
| `timestamp` | 13 位毫秒时间戳 |
| `nonce` | 随机字符串，建议 32 位，不可重复使用 |

这两个参数参与签名，须先补齐再计算 sign。

**第 3 步：拼接待签名字符串 paramsStr**

key 按字典序升序排列，拼成 `k1=v1&k2=v2`：

```
age=18&name=zhang&nonce=abc123&sex=女&timestamp=1792807881462
```

| 规则 | 说明 |
|------|------|
| 排序 | key 按字典序升序 |
| 空值跳过 | `null` 或 `""` 的整条不参与拼接 |
| 不做 URL 编码 | 用原始值拼接，URL 编码只用于传输 |
| 排除 sign | 集合中若含 `sign`，计算时剔除 |
| 字符编码 | UTF-8 |

**第 4 步：计算摘要**

HMAC 系列（`hmac-md5` / `hmac-sha256` / `hmac-sha512`）：

```
sign = HMAC(secretKey, paramsStr)
```

非 HMAC 系列（`md5` / `sha1` / `sha256` / `sha384` / `sha512`）：

```
sign = digest(paramsStr + "&key=" + secretKey)
```

输出小写十六进制字符串。

### 2.2 支持的摘要算法

| digestAlgo | 输出长度 |
|-----------|---------|
| `md5` | 32 |
| `sha1` | 40 |
| `sha256` | 64 |
| `sha384` | 96 |
| `sha512` | 128 |
| `hmac-md5` | 32 |
| `hmac-sha256` | 64 |
| `hmac-sha512` | 128 |

### 2.3 JSON body 展平规则

| JSON | 展平结果 |
|------|---------|
| `{"name":"nzxy"}` | `name=nzxy` |
| `{"user":{"name":"nzxy","age":18}}` | `user.name=nzxy`、`user.age=18` |
| `{"tags":["x","y"]}` | `tags[0]=x`、`tags[1]=y` |
| `{"items":[{"id":1}]}` | `items[0].id=1` |
| `{"price":18.5}` | `price=18.5` |
| `{"vip":true}` | `vip=true` |
| `{"nil":null}` | 不参与签名 |

数值与布尔：整数 `18` → `"18"`（不是 `18.0`），布尔 `true` → `"true"`（小写）。

### 2.4 appId 传递

通过请求头 `X-Sign-App-Id` 传递，不参与签名。

### 2.5 算法自测锚点

```
secretKey = SwqFmsKxcbq23
参数: name=zhang, age=18, sex=女
paramsStr = age=18&name=zhang&sex=女
```

| 算法 | 期望 sign |
|------|----------|
| `md5` | `6f5e844a53e74363c2f6b24f64c4f0ff` |
| `hmac-sha256` | `f2cb11bddf000a4c71f8bd280cab65a84d99f1b4c490a6fbbbe49fffec7203cb` |
| `hmac-md5` | `269c49e0541d24e9732895db2af7944d` |

## 三、调用方式

四种形态，服务端按 Content-Type 自动识别。

| 形态 | HTTP 方法 | Content-Type | 业务参数位置 | 三件套位置 |
|------|----------|--------------|-------------|-----------|
| query 参数 | GET | — | URL query | URL query |
| form 表单 | POST | `application/x-www-form-urlencoded` | 表单 body | 表单 body |
| JSON body | POST / PUT | `application/json` | JSON body | 请求头 |
| 路径参数 | GET / POST | 任意 | URL path + query | query 或 header |

### 3.1 query 参数

```http
GET /demo/form/query?name=nzxy&age=18&timestamp=1792807881462&nonce=abc123&sign=8f4a2c1e... HTTP/1.1
Host: api.example.com
X-Sign-App-Id: thirdA
```

### 3.2 form 表单

```http
POST /demo/form-body HTTP/1.1
Host: api.example.com
X-Sign-App-Id: thirdA
Content-Type: application/x-www-form-urlencoded; charset=UTF-8

name=nzxy&age=18&timestamp=1792807881462&nonce=abc123&sign=8f4a2c1e...
```

### 3.3 JSON body

```http
POST /demo/json-body HTTP/1.1
Host: api.example.com
X-Sign-App-Id: thirdA
timestamp: 1792807881462
nonce: abc123
sign: 8f4a2c1e9b3d5f7a0e2c4b6d8f1a3e5c7b9d0f2a4c6e8b1d3f5a7c9e0b2d4f6a
Content-Type: application/json; charset=UTF-8

{"name":"nzxy","age":18}
```

JSON 模式下三件套走请求头。

### 3.4 路径参数

```http
GET /demo/form/path/G001?name=nzxy&timestamp=1792807881462&nonce=abc123&sign=... HTTP/1.1
Host: api.example.com
X-Sign-App-Id: thirdA
```

加签参数集合 = `{goodsId: G001, name: nzxy, timestamp, nonce}`。

### 3.5 多值参数

同名参数传多次时，只取第一个值参与签名。

### 3.6 中文与特殊字符

签名计算用原始值，HTTP 传输时正常 URL 编码：

```
签名计算:  remark=测试&特殊=字符
URL 传输:  remark=%E6%B5%8B%E8%AF%95%26%E7%89%B9%E6%AE%8A%3D%E5%AD%97%E7%AC%A6
```

## 四、代码示例

### 4.1 最简用法

```java
import com.wxl52d41.apisign.client.SignClient;

SignClient signClient = new SignClient(
        "thirdA",                          // appId
        "thirdA-secret-key-please-change", // secretKey
        "hmac-sha256"                      // digestAlgo
);

Map<String, String> params = new LinkedHashMap<>();
params.put("name", "nzxy");
params.put("age", "18");

SignClient.SignTrio trio = signClient.sign(params);
trio.getTimestamp();
trio.getNonce();
trio.getSign();
```

### 4.2 JSON body + RestTemplate

```java
Map<String, Object> body = new LinkedHashMap<>();
body.put("name", "nzxy");
body.put("age", 18);

SignClient.SignTrio trio = signClient.signJsonBody(body);

HttpHeaders headers = new HttpHeaders();
headers.setContentType(MediaType.APPLICATION_JSON);
trio.toHeaders("thirdA").forEach(headers::set);

String resp = new RestTemplate().postForObject(
        "https://api.example.com/demo/json-body",
        new HttpEntity<>(body, headers), String.class);
```

### 4.3 表单 + RestTemplate

```java
SignClient.SignTrio trio = signClient.sign(params);
Map<String, String> form = trio.intoParams(params);

MultiValueMap<String, String> map = new LinkedMultiValueMap<>();
form.forEach(map::add);

HttpHeaders headers = new HttpHeaders();
headers.setContentType(MediaType.APPLICATION_FORM_URLENCODED);
headers.set(SignClient.APP_ID_HEADER, "thirdA");

new RestTemplate().postForObject("https://api.example.com/demo/form-body",
        new HttpEntity<>(map, headers), String.class);
```

### 4.4 路径参数

```java
Map<String, String> signParams = new LinkedHashMap<>();
signParams.put("goodsId", "G001");
signParams.put("name", "nzxy");

SignClient.SignTrio trio = signClient.sign(signParams);

Map<String, String> query = new LinkedHashMap<>();
query.put("name", "nzxy");
query.put(SignClient.TIMESTAMP, trio.getTimestamp());
query.put(SignClient.NONCE, trio.getNonce());
query.put(SignClient.SIGN, trio.getSign());
```

### 4.5 非 Java 实现

```
1. params 的 key 按字典序升序
2. 跳过 null 和 "" 的值
3. 拼成 k=v&k=v（不做 URL 编码）
4. hmac-*  → HMAC(key=secretKey, data=paramsStr)
   其他     → digest(paramsStr + "&key=" + secretKey)
5. 转小写十六进制
```

## 五、请求约束

| 项目 | 值 |
|------|-----|
| timestamp 格式 | 13 位毫秒数字 |
| timestampDisparity | 由我方分配，默认 900000（15 分钟） |
| nonce 记录有效期 | `timestampDisparity * 2 + 2` 秒 |
| 请求体大小上限 | 2 MB |
| JSON 嵌套层数 | 32 |
| appId 请求头 | `X-Sign-App-Id` |
| 三件套参数名 | `timestamp` / `nonce` / `sign` |

每次请求（含重试）重新生成 timestamp、nonce、sign。

## 六、错误码

| code | 消息 | HTTP | 触发条件 |
|------|------|------|---------|
| 12201 | 参与参数签名的秘钥不可为空 | 401 | 服务端 secretKey 未配置 |
| 12202 | 无效签名：{sign} | 401 | sign 不一致 |
| 12202 | 此 nonce 已被使用过，不可重复使用：{nonce} | 401 | nonce 重复 |
| 12203 | timestamp 超出允许的范围：{timestamp} | 401 | 超出时间窗 |
| 12204 | 缺少 timestamp 字段 | 400 | 未传 timestamp |
| 12204 | 缺少 nonce 字段 | 400 | 未传 nonce |
| 12204 | 缺少 sign 字段 | 400 | 未传 sign |
| 12204 | nonce 为空，无效 | 400 | nonce 为空字符串 |
| 12204 | timestamp 格式非法：{value} | 400 | timestamp 非纯数字 |
| 12205 | 不支持的摘要算法：{algo} | 401 | 算法不在白名单 |
| 12206 | 请求体超过允许的大小：{n} 字节 | 400 | body > 2MB |
| 12206 | 请求体必须为 JSON 对象 | 400 | body 非 `{}` |
| 12206 | 读取或解析请求体失败：{msg} | 400 | body 非法 JSON |
| 12206 | 请求体嵌套层级过深，超出允许范围：32 | 400 | 嵌套 > 32 层 |
| 12206 | 摘要计算失败：{algo} | 401 | JVM 不支持该算法 |
| 12207 | 缺少 appId，请通过请求头 X-Sign-App-Id 传递 | 400 | 未传 appId |
| 12208 | 未登记的 appId：{appId} | 401 | appId 不存在 |
| 12209 | appId 已停用：{appId} | 401 | appId 被关闭 |
| 12210 | appId 无权访问该接口：{appId} | 401 | 接口未授权该 appId |

响应体：

```json
{
  "code": 12202,
  "message": "无效签名：8f4a2c1e...",
  "data": null
}
```

以响应体 `code` 为准判断成败。
